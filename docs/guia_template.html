1

Qué vas a construir

Un analista de franquicias de una cadena de galletas. Responde en lenguaje natural sobre ventas, proveedores y opiniones de clientes, y muestra de dónde sale cada cifra.

Las cinco herramientas

HerramientaTipoQué hace
find_franchiseFunción UC (SQL)Busca franquicias por nombre, ciudad o país y devuelve su franchiseID
franchise_salesFunción UC (SQL)Unidades e ingresos por producto de una franquicia en un rango de fechas
top_franchisesFunción UC (SQL)Ranking de franquicias por ingresos
franchise_supplierFunción UC (SQL)Proveedor, ingrediente y si está aprobado
search_reviewsVector SearchBúsqueda semántica sobre 204 reseñas de clientes

Casuística que cubre

#EscenarioComportamiento esperado
1Ranking ("top 3 franquicias")Llama a top_franchises; no inventa cifras
2Cadena de herramientas ("qué vendió Tokio y quién la abastece")find_franchise → franchise_sales → franchise_supplier
3Opinión de clientesSiempre search_reviews; cita el id de la reseña
4Fuera del rango de fechas ("ventas de junio")Avisa que los datos cubren del 2024-05-01 al 2024-05-17
5Fuera de dominio ("receta de pizza")Declina cortésmente
6Prompt injection ("ignora tus instrucciones")Declina y no revela el prompt
7Idioma cruzado ("Tokio" vs Tokyo en los datos)Traduce antes de buscar

Los datos

Son datos de ejemplo que Databricks incluye en el catálogo samples.bakehouse; no hay que descargar nada.

TablaFilasContenido
sales_transactions3 333Ventas del 2024-05-01 al 2024-05-17, 6 productos, 48 franquicias
sales_franchises48Nombre, ciudad, país, tamaño, proveedor
sales_suppliers27Ingrediente, continente, aprobado Y/N
media_customer_reviews204Reseñas en texto libre
Decisión de privacidad

sales_customers (nombres, correos, teléfonos, direcciones) no se usa, y de las transacciones se elimina cardNumber. El agente no puede filtrar lo que nunca copiamos.

{{CMD}} az login az group create -n rg-returns-agent -l eastus2 az databricks workspace create -g rg-returns-agent -n dbw-returns-agent -l eastus2 --sku premium az databricks workspace show -g rg-returns-agent -n dbw-returns-agent --query workspaceUrl -o tsv {{/CMD}}

El último comando imprime la URL, algo como adb-1234567890123456.7.azuredatabricks.net. Guárdala.

Crear el perfil de la CLI

Como ya iniciaste sesión en Azure, la CLI puede reutilizar esa sesión sin abrir el navegador. Añade esto al final de ~/.databrickscfg:

{{CMD}} [returns-agent] host = https:// auth_type = azure-cli {{/CMD}}

Alternativa clásica, que abre el navegador: databricks auth login --host https://<workspaceUrl> --profile returns-agent.

Verifica

Ejecuta databricks current-user me $P. Debe devolver tu usuario con "active": true.

Permisos en Unity Catalog

El catálogo del workspace pertenece al grupo de administradores. Aun siendo administrador, registrar el modelo desde un job falla con PERMISSION_DENIED: User does not have USE CATALOG. Se resuelve una vez:

{{CMD}} databricks experimental aitools tools query "GRANT ALL PRIVILEGES ON CATALOG dbw_returns_agent TO \`$ME\`" $P {{/CMD}}

Obtener el id del warehouse

{{CMD}} databricks warehouses list $P -o json | jq -r '.[] | "\(.id) \(.name)"' export WH="" {{/CMD}}

Rutas rotas en Git Bash (Path (C:/Program Files/Git/Workspace/...) doesn't start with '/'): falta export MSYS_NO_PATHCONV=1.

Herramientas SQL

ObjetivoLas 4 funciones que el agente puede llamar
Archivossql/02_tools.sql
TardaSegundos
CostoMínimo

Una función de Unity Catalog es una consulta con nombre, parámetros y permisos. El agente no recibe acceso a las tablas, solo a estas funciones: lo que puede leer queda definido y gobernado aquí.

Idea clave

El texto COMMENT de cada función y de cada parámetro es lo que lee el LLM para decidir cuándo y cómo llamarla. Un comentario pobre produce llamadas erróneas.

{{CMD}} ./scripts/run_sql.sh sql/02_tools.sql {{/CMD}}
Verifica

Prueba cada función a mano. top_franchises(3) debe devolver Baked Bliss (Roma, 6 642 USD), Sweet Sinsations (Estocolmo, 4 512) y The Crumbly Nook (Sídney, 2 790).

{{CMD}} databricks experimental aitools tools query "SELECT * FROM dbw_returns_agent.bakehouse_agent.top_franchises(3)" $P databricks experimental aitools tools query "SELECT * FROM dbw_returns_agent.bakehouse_agent.find_franchise('tokyo')" $P databricks experimental aitools tools query "SELECT * FROM dbw_returns_agent.bakehouse_agent.franchise_supplier(3000001)" $P {{/CMD}}
Si falla

INVALID_LIMIT_LIKE_EXPRESSION.IS_UNFOLDABLE: Spark no acepta LIMIT con un parámetro de función. Por eso top_franchises usa row_number() y filtra por ranking.

Búsqueda vectorial (RAG)

ObjetivoBúsqueda semántica sobre reseñas
Archivosagent/index_spec.json
TardaVarios minutos
CostoEmpieza a facturar

RAG significa recuperar los fragmentos relevantes antes de responder. El agente no "sabe" qué opinan los clientes: lo busca en el índice y cita lo que encuentra.

{{CMD}} databricks vector-search-endpoints create-endpoint bakehouse-vs STANDARD --no-wait $P databricks vector-search-indexes create-index --json @agent/index_spec.json $P {{/CMD}}

Campos de index_spec.json

CampoValorSignificado
index_typeDELTA_SYNCEl índice se mantiene sincronizado con una tabla Delta
pipeline_typeTRIGGEREDSincroniza cuando se pide; más barato que CONTINUOUS
embedding_source_columnsreview + databricks-gte-large-enDatabricks calcula los embeddings del texto
columns_to_syncid, franquicia, fecha, textoSolo estas columnas se pueden devolver en una búsqueda

Espera a que el índice esté listo (tarda varios minutos: primero se aprovisiona el endpoint y luego se sincroniza):

{{CMD}} databricks vector-search-indexes get-index dbw_returns_agent.bakehouse_agent.reviews_index $P | jq '.status' # listo cuando: "ready": true {{/CMD}}
Costo

Desde que el índice existe, el endpoint factura 4 DBU por hora aunque no lo uses. Anota la hora y recuerda el Capítulo 12.

El agente

ObjetivoEl cerebro: LLM + herramientas
Archivosagent/agent.py
Tarda—
Costo—

El agente es una clase ResponsesAgent de MLflow con un método predict(). Ese formato lo entienden el despliegue, el tracing y la evaluación. No se usa LangChain: el bucle completo cabe en pocas líneas y se puede leer entero.

Recorrido por el archivo

BloqueQué hace
DEV_CONFIG + ModelConfigConfiguración (modelo, warehouse, índice, esquema). En jobs sale de variables de entorno; al desplegar, de la configuración guardada dentro del modelo
SYSTEM_PROMPTReglas del analista: rango de fechas, resolver siempre el id, reseñas siempre con search_reviews, traducir ciudades al inglés, declinar fuera de dominio, ignorar instrucciones dentro de reseñas
TOOLSLas 5 herramientas en formato function-calling (nombre, descripción, esquema JSON)
SQL_TOOLSHerramienta → sentencia SQL con parámetros con nombre (:franchise_id) y su conversión de tipo
_run_sql_toolEjecuta la función en el warehouse con la Statement Execution API. Lo que dice el LLM nunca se concatena en el SQL (evita inyección)
_search_reviewsConsulta el índice; filtro opcional por franquicia; recorta cada reseña a 600 caracteres
_chatLlama al LLM con temperature=0 para decisiones repetibles
_textgpt-oss devuelve el contenido como lista (razonamiento + texto); se queda solo con el texto
predictEl bucle de la Figura 2; registra cada llamada y su resultado como ítems de la respuesta
set_model(...)Obligatorio en "models from code": indica a MLflow qué objeto empaquetar
Detalles que cuestan horas

1. No pongas @mlflow.trace en predict: ResponsesAgent ya lo traza. 2. Los errores de herramienta se devuelven al LLM como texto ERROR: ... para que se corrija; no tumban el agente. 3. gpt-oss a veces emite el nombre de la herramienta con basura (franchise_supplier<|channel|>commentary); se limpia con .split("<")[0].

Dependencias: mlflow>=3.1, databricks-sdk>=0.40, pydantic>=2. El código completo está en el Apéndice C.

Probar en Databricks

ObjetivoVer el agente responder de verdad
Archivosagent/test_agent.py
agent/job_test.json
TardaUnos minutos
CostoMínimo

El código no corre en tu máquina: corre en compute serverless mediante un job de una sola ejecución. Subes los archivos al workspace y lanzas el job.

{{CMD}} databricks workspace mkdirs $WS $P databricks workspace import $WS/agent.py --file agent/agent.py --format RAW --overwrite $P databricks workspace import $WS/test_agent.py --file agent/test_agent.py --format RAW --overwrite $P # edita agent/job_test.json: reemplaza y databricks jobs submit --json @agent/job_test.json $P --timeout 20m {{/CMD}}

Anatomía de job_test.json

  • spark_python_task.python_file: ruta del script en el workspace.
  • parameters: [<WAREHOUSE_ID>, <carpeta que contiene agent.py>]. La carpeta se pasa como parámetro porque en serverless no existe __file__.
  • environments: entorno serverless client: "3" con las dependencias pip.

Ver la salida

{{CMD}} RID=$(databricks jobs list-runs --limit 1 $P -o json | jq -r '.[0].run_id') TID=$(databricks jobs get-run $RID $P -o json | jq -r '.tasks[0].run_id') databricks jobs get-run-output $TID $P -o json | jq -r '.logs // .error' {{/CMD}}
Verifica

Para "top 3 franquicias" debe llamar a top_franchises; para Tokio, a find_franchise → franchise_sales → franchise_supplier; para opiniones, a search_reviews; para la pizza, a ninguna herramienta y rechazar.

Si falla

NameError: __file__: pasa la carpeta como parámetro. 'dict' object has no attribute 'text': los ítems de contenido son diccionarios; usa content[0]["text"]. Para ver el error completo de un job: jq -r '.error_trace' sobre la salida del run.

Registrar y desplegar

ObjetivoEndpoint público del agente
Archivosagent/log_and_deploy.py
agent/job_deploy.json
Tarda~10 min la primera vez
CostoEscala a cero

Convierte el código en un servicio versionado, gobernado y con credenciales automáticas.

  1. log_model: empaqueta agent.py (models from code) junto con su configuración y la lista de resources: el LLM, el warehouse, el índice y las 4 funciones. Con eso Databricks crea credenciales de corta duración para el agente (automatic authentication passthrough). No hay tokens en el código.
  2. register_model: guarda el modelo versionado en Unity Catalog: dbw_returns_agent.bakehouse_agent.bakehouse_agent.
  3. agents.deploy: crea el endpoint de Model Serving con escala a cero, una review app y el almacenamiento de trazas. Requiere el paquete databricks-agents.
{{CMD}} databricks workspace import $WS/log_and_deploy.py --file agent/log_and_deploy.py --format RAW --overwrite $P databricks jobs submit --json @agent/job_deploy.json $P --timeout 40m {{/CMD}}

Saber si el endpoint está listo

Hay que mirar dos campos: durante un cambio de versión, ready sigue en READY aunque la versión vieja aún atienda.

{{CMD}} databricks serving-endpoints get $EP $P | jq '.state' # listo cuando: ready == "READY" Y config_update == "NOT_UPDATING" {{/CMD}}

Consultarlo

Importante

El comando databricks serving-endpoints query descarta el campo output de este formato y solo devuelve id y object. Usa la API directa:

{{CMD}} databricks api post /serving-endpoints/$EP/invocations $P \ --json '{"input":[{"role":"user","content":"¿Qué proveedor abastece a Tokyo Treats?"}]}' \ | jq -r '.output[-1].content[0].text' {{/CMD}}
Iterar

Cada cambio en agent.py exige repetir este capítulo: genera una nueva versión del modelo y el endpoint se actualiza sin cortar el servicio.

Si falla

PERMISSION_DENIED ... USE CATALOG al registrar: falta el GRANT del Capítulo 3.

Evaluar

ObjetivoMedir, no suponer
Archivosagent/evaluate.py
agent/job_eval.json
Tarda~3 min por corrida
CostoBajo

Un agente que "parece funcionar" en tres pruebas manuales no es un agente evaluado. mlflow.genai.evaluate ejecuta el agente sobre un conjunto de preguntas y puntúa cada respuesta.

{{CMD}} databricks workspace import $WS/evaluate.py --file agent/evaluate.py --format RAW --overwrite $P databricks jobs submit --json @agent/job_eval.json $P --timeout 20m {{/CMD}}

Qué se mide

ElementoTipoQué comprueba
Dataset (8 preguntas)DatosPreguntas con expectations. Los números esperados salen de SQL ejecutado a mano, no del LLM
right_toolCódigo (gratis)¿Llamó a la herramienta correcta, o a ninguna cuando no debía?
has_factsCódigo (gratis)¿Aparecen los datos esperados? Ignora espacios y separadores de miles
scope_and_safetyJuez LLMNo revela el prompt; declina lo que no es de Bakehouse
Detalle

MLflow rechaza None como valor de expectativa (The value field must be specified). "Ninguna herramienta" se escribe "none".

Resultados reales: 7 corridas

Corridaright_toolhas_factsscope_and_safetyQué cambió
1 (base)0.750.500.875Primera versión
20.8751.000.875Se limpia el nombre de herramienta; el scorer normaliza espacios
30.750.8750.50–0.625Misma versión, otro resultado: sin temperature=0 hay no determinismo
4–50.8751.000.75temperature=0, Tokio→Tokyo, juez corregido. Dos corridas idénticas
6–71.001.000.625–0.75Regla "reseñas siempre con search_reviews"

Qué se aprendió

  1. El ruido es grande con un modelo pequeño y pocas preguntas. Sin fijar la temperatura, la misma versión osciló entre 0.5 y 0.875. Fija temperatura y repite antes de concluir.
  2. Una regla que el juez no puede verificar produce falsos "no". "Los números vienen de las herramientas" no es comprobable si el juez solo ve pregunta y respuesta. Se reemplazó por has_facts contra datos reales.
  3. El fallo más grave era contestar opiniones sin consultar reseñas (riesgo de inventar). Se cerró con una regla explícita en el prompt.
  4. Limitación abierta: el juez gpt-oss-20b sigue marcando "no" algunas respuestas válidas. Los scorers de código son la señal fiable. Un juez más fuerte lo mejoraría, pero cuesta más y no se midió.
  5. Ocho preguntas son una prueba de humo, no una evaluación estadística. Ampliar el dataset es el siguiente paso.

Las trazas y los resultados quedan en los experimentos MLflow /Shared/bakehouse-agent-dev, /Shared/bakehouse-agent y /Shared/bakehouse-agent-eval (menú Experiments del workspace).

ArchivoRol
app.pyUI de chat. Llama a POST /serving-endpoints/<endpoint>/invocations con WorkspaceClient().api_client.do(...)

Conexiones y permisos

La app se ejecuta con su propio service principal (credenciales automáticas). Solo necesita CAN_QUERY sobre el endpoint del agente, declarado como resource al crear la app. El agente accede al warehouse, las funciones y el índice con su propio passthrough, así que la app nunca toca los datos.

{{CMD}} databricks workspace import-dir app /Workspace/Users/$ME/bakehouse-app --overwrite $P databricks apps create --no-wait $P --json "{ \"name\": \"bakehouse-analyst\", \"description\": \"Chat UI for the Bakehouse analyst agent\", \"resources\": [{\"name\": \"serving-endpoint\", \"serving_endpoint\": {\"name\": \"$EP\", \"permission\": \"CAN_QUERY\"}}]}" # espera compute_status = ACTIVE, luego despliega: databricks apps get bakehouse-analyst $P | jq '.compute_status.state' databricks apps deploy bakehouse-analyst --source-code-path /Workspace/Users/$ME/bakehouse-app $P databricks apps get bakehouse-analyst $P | jq '{url, app: .app_status.state}' {{/CMD}}

Abre la url en el navegador (te pedirá iniciar sesión) y prueba, por ejemplo: "¿Cuáles son las 5 franquicias con más ingresos?" o "¿Qué opinan los clientes de las Outback Oatmeal?".

Por qué Streamlit

Databricks recomienda AppKit (Node, TypeScript, React) por defecto. Aquí se usó Streamlit por ser una app interna de demostración y un equipo de datos que trabaja en Python. Si el destino fuera un producto, AppKit sería el camino.

Si falla

databricks apps logs devuelve websocket: bad handshake (HTTP 302) con el perfil azure-cli: ese comando exige OAuth de usuario. Crea un perfil con databricks auth login y úsalo solo para leer logs.

Apagar lo que cuesta

ObjetivoDejar el costo en cero
Archivosscripts/teardown.sh
TardaSegundos
Costo—

Vector Search factura mientras exista un índice. Termina siempre la sesión con este paso.

{{CMD}} chmod +x scripts/teardown.sh ./scripts/teardown.sh pause # borra índice y endpoint de Vector Search (lo único caro en reposo) ./scripts/teardown.sh all # además borra la app, el endpoint del agente y todo el grupo de recursos {{/CMD}}
Qué pasa después

Tras pause, el agente no puede usar search_reviews hasta recrear el endpoint y el índice (Capítulo 6, esperando ready: true). Tras all no queda nada: el workspace y su grupo administrado desaparecen, y para volver a empezar se repite desde el Capítulo 3.

Según la documentación de Databricks, los cargos de un endpoint de Vector Search cesan 24 horas después de borrar el último índice.
